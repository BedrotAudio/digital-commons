# Implementation Notes

Verified facts for implementers, established by reading library source and by
running probes on 2026-11-01 against Bubble Tea v2.1.1, Lip Gloss v2.0.6, Bubbles
v2.2.1, Glamour v2.0.1 and Ollama 0.40.13. Recheck them when upgrading a dependency.

Not physically verified: a real Shift+Enter keypress in a Windows Terminal window,
paste from a real clipboard, and OSC 52 reaching the real clipboard. Treat these as
manual checks.

## Terminal decisions

### Shift+Enter sends the message on Windows unless the app turns on win32-input mode

On Windows, Init returns tea.Sequence(tea.Raw(ansi.SetModeWin32Input), tea.Raw(ansi.RequestModeWin32Input)). After p.Run() returns, write ansi.ResetModeWin32Input to stdout with ENABLE_VIRTUAL_TERMINAL_PROCESSING turned on for that one write, then put the output mode back. By then Bubble Tea has restored the console mode it found, and a classic console window starts with that flag off: there the sequence printed as the text `←[?9001l` and the mode stayed on, so a later program in the window that read VT input got key records such as `\x1b[65;0;97;1;0;1_` for `a` (seen in a hidden conhost from cmd.exe and Windows PowerShell 5.1; ConPTY windows were not affected). Set ta.KeyMap.InsertNewline.SetKeys("shift+enter", "ctrl+j", "ctrl+enter"). Win32 mode adds release events and modifier-only presses, so match tea.KeyPressMsg and never tea.KeyMsg, and pass tea.WithFilter that drops tea.KeyReleaseMsg and KeyPressMsg with Code in tea.KeyLeftShift..tea.KeyIsoLevel5Shift. Always show Ctrl+J in the footer. Show Shift+Enter only after tea.ModeReportMsg{Mode: ansi.ModeWin32Input, Value: ansi.ModeSet} or KeyboardEnhancementsMsg.SupportsKeyDisambiguation(). Reword the architecture.md row to say the app enables this mode itself.

### Win32-input mode is requested only where the terminal around the console host honours it

Found by the end-to-end harness. The console host asks its terminal for win32-input mode and answers the app's own mode query itself, so a yes proves nothing about the terminal. A terminal that ignores the request sends plain sequences, and with the app's mode on the host delivers an arrow key as stray text such as `;0;27;1;0;1_[B`. main.go therefore requests the mode when WT_SESSION is set, or when TERM, TERM_PROGRAM and SSH_CONNECTION are all empty, which is a bare console window. Any other terminal gets plain keys and the Ctrl+J hint, and there Shift+Enter sends, which the hint does not contradict. Windows Terminal itself sends every key as win32-input records, so the harness does the same.

### 'The UI paints every cell' is not achievable with styles or View.BackgroundColor

Paint at cell level as the last step of each region: c := lipgloss.NewCanvas(w, h); c.Compose(lipgloss.NewLayer(s)); for every CellAt(x, y) set Style.Bg and Style.Fg when nil; return c.Render(). Run this after viewport and glamour, with the region's token colour. Skip it when the profile is ASCII or lower. Leave View.BackgroundColor and View.ForegroundColor nil. Leave glamour's Document.Color unset and let paint fill the default foreground, because setting it grew a 4 KB render from 23 KB to 277 KB of ANSI and from 8 ms to 20 ms.

### bubbles filepicker cannot meet the File picker panel requirements

Do not use bubbles/filepicker. Write a small internal picker: os.ReadDir, case-insensitive extension filter from bootstrap limits.attachment_extensions, start at os.UserHomeDir(), a drive row on Windows, rows truncated to panel width, up/down/enter/backspace keys, click and wheel handling, Esc closes. It reuses the same row rendering as the sidebar.

### Glamour passes raw escapes through, and ansi.Strip alone is not the required sanitizer

Add one internal Clean(s) and call it before any rendering: strings.Map over ansi.Strip(s), keep \n and \t, drop everything where unicode.IsControl(r) is true. Apply it to the accumulated reply on each render, not to each delta, because a sequence can straddle deltas. Apply it also to thinking text, titles, citations, error messages, file names and pasted text. Add a test with ESC]52, ESC[2J, CR and U+009B inside prose, a code span and a fence.

### textarea with MaxHeight 6 refuses new lines at six instead of scrolling

Configure the composer as: ta.ShowLineNumbers = false; ta.Prompt set; ta.DynamicHeight = true; ta.MinHeight = 1; ta.MaxHeight = 6; ta.MaxContentHeight = 10000; then ta.SetWidth(w). Leave CharLimit at 0, because it silently truncates paste, and check bootstrap limits.max_message_chars at send with a plain-language notice.

### 'auto' theme has no built-in fallback because a terminal may never answer

In Init, tea.Batch(tea.RequestBackgroundColor, tea.Tick(250*time.Millisecond, themeTimeout)). Render an empty view until the reply or the timeout, so a light terminal does not flash dark. On timeout use dark. Query once per run and keep the result, so Ctrl+T returning to auto reuses it.

### Glamour cannot number, frame or locate code blocks

Parse the Markdown once with goldmark (already in the module graph through glamour) and split it at top-level fenced code blocks. Render prose with glamour and render each code block with an own frame around chroma output. Record the line of each [1], Copy and Try again as they are rendered, and resolve clicks with msg.Mouse().Y + vp.YOffset() minus the viewport's top row. Use FencedCodeBlock nodes as the source for /copy code and Ctrl+Y. Fences nested in lists or quotes stay with glamour: set ChromaFormatter to "terminal16m" and StyleCodeBlock.Theme to a chroma style registered per theme, because StyleCodeBlock.Chroma registers one global style and cannot hold both themes.

### NO_COLOR is only partly honoured by the libraries

In main: if os.Getenv("NO_COLOR") != "" add tea.WithColorProfile(colorprofile.ASCII). This keeps bold and other decoration and removes all colour at the renderer. Keeping View.BackgroundColor nil (see the painting issue) covers the OSC case. Add a test that asserts a frame carries no colour SGR under that profile.

### CRLF paste is double-spaced by textarea

Handle tea.PasteMsg in the root Update: replace \r\n and \r with \n, run Clean, then forward tea.PasteMsg{Content: cleaned} to the textarea. Disable ta.KeyMap.Paste and bind ctrl+v at the root to a Cmd that calls clipboard.ReadAll and returns the same tea.PasteMsg. Add a manual check that pastes CRLF text in Windows Terminal with win32 mode on, because under that mode ConPTY delivered \r\n to the app as \n\n, which normalization cannot repair.

## Ollama and gateway facts

- Ollama 0.40.13 streaming /api/chat returns application/x-ndjson. Chunks carry message.content and message.thinking; the final chunk has done:true, done_reason (stop or length), total_duration, load_duration, prompt_eval_count, prompt_eval_cached_count, prompt_eval_duration, eval_count and eval_duration, all durations in nanoseconds. The final chunk's content is empty. A client abort produces no final chunk, so usage must be estimated on cancel.
- prompt_eval_count includes cached tokens (23 total, 18 cached on a repeat), so it is safe for usage.prompt_tokens. Reasoning tokens count in eval_count and against num_predict.
- Preload with messages:[] returns application/json, one object with done_reason load and no duration fields.
- /api/ps fields are name, model, size, size_vram, context_length and expires_at. It returned [] during a load, and took 223 to 1467 ms per call on this machine. Requesting num_ctx 1024 loaded at context_length 2048, so a context below 2048 is not honoured. 8192 and 4096 load exactly.
- truncate:false gives HTTP 400 with body {"error":"request (3078 tokens) exceeds the available context size (2048 tokens), try increasing it"} in 0.7 s. shift:false made no difference: generation stopped with length at the context limit either way. Default truncation kept about half the context: 1027 of 2048.
- Omitting keep_alive still showed a 30 minute expiry in this session with OLLAMA_KEEP_ALIVE unset, so omission did not reset it here. Send it on every request anyway, because config is the contract.
- Chars per token: 4.78 on real English (requirements.md, 8308 chars, 1739 tokens); 6.65 to 6.84 on synthetic word lists. CSV was not measured. Single short prompts carry about 13 tokens of template overhead.
- Cancellation tests used Starlette 1.9.0 and uvicorn 0.54.0 directly. fastapi is not installed in system Python and was not downloaded; FastAPI re-exports the Starlette StreamingResponse, but rerun these checks in the pinned venv. uvicorn declares ASGI spec_version 2.3, which selects the listen_for_disconnect path in Starlette.
- Go client notes: read SSE with bufio.Reader rather than a default bufio.Scanner, trim CR as well as LF, and leave http.Client.Timeout at zero.
- FastAPI's default validation and HTTPException bodies do not match the contract's error shape, so handlers for RequestValidationError, HTTPException and Starlette 404/405 are required.

## Security facts

- Ollama 0.40.13 cloud gate: GET /api/status returns {"cloud":{"disabled":bool,"source":"none|env|config"}}. Persistent switch: ~/.ollama/server.json with {"disable_ollama_cloud": true}. Env switch: OLLAMA_NO_CLOUD=1. Refusal is HTTP 403 with error 'ollama cloud is disabled: remote model is unavailable' on /api/chat and /api/generate; /v1/chat/completions wraps the same text in an error object.
- Cloud stubs show top-level remote_model and remote_host in /api/tags, /api/show and chat responses, including the streamed reply tested, plus empty details and a size of about 150 bytes. The real Gemma4:12b has neither field and details.format gguf. Ollama resolves names case-insensitively (gemma4:12B matched Gemma4:12b), so installed-model comparison must be too.
- Gemma4:12b advertises capabilities completion, vision, audio, tools, thinking. The adapter must never send tools, format, raw or template, and must read only message.content, message.thinking and the done statistics. Injection cannot widen access only while that holds, identity comes solely from the token, and retrieval filters before ranking. Attachment and document text goes in a delimited user-role block, never in system; delimiters are not a security boundary.
- httpx 0.28.1 follows no redirects by default, but pin follow_redirects=False anyway. Do not pass verify as a string, which is deprecated; pass an ssl context.
- Loopback checks must parse, not prefix-match. Go: url.Hostname(), then lower-cased 'localhost' or net.ParseIP(h).IsLoopback(). Under that check 127.0.0.1.evil.gov, localhost.evil.gov, 127.0.0.1@evil.gov, 0.0.0.0, 127.1 and 2130706433 are all rejected, and LOCALHOST passes only with lower-casing. Python equivalent: ipaddress.ip_address(host).is_loopback or host.lower() == 'localhost'.
- Starlette 1.9.0 TrustedHostMiddleware with the configured allowed_client_hosts rejects Host [::1]:port, so add it only if the gateway ever binds IPv6. docs_enabled: false must set docs_url, redoc_url and openapi_url to None so /openapi.json is also closed.
- Go's ProxyFromEnvironment caches the environment on first use, so tests must set proxy variables before any request or use a custom Transport. My first Go run showed a false nil for this reason; the re-run is what the findings report.
- pydantic 2.14.1: hide_input_in_errors cleans str(exc) only, and errors() still includes input. Use errors(include_input=False) anywhere errors are logged or returned.
- SQLite: secure_delete is per connection, so set it in the connection factory. Use a size cap in middleware for request bodies, since the designed limits are checked only after parsing.
