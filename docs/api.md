# Digital Commons Gateway API, v1

This is the contract between the terminal and the gateway. Change it here first.
The separate model-host contract is at the end: any FastAPI server implementing
it can serve as the organization model server.

## Conventions

- Base URL comes from the terminal's `gateway.base_url`, by default
  `http://127.0.0.1:8000`.
- Requests and responses are JSON unless stated otherwise. `POST` requires
  `Content-Type: application/json`.
- Times are UTC ISO 8601, for example `2026-11-01T20:39:12Z`.
- Identifiers match `^[A-Za-z0-9_-]{1,64}$`. Anything else in a path returns 422.
- `Authorization: Bearer <token>` is required on every `/v1/*` route, in every
  identity mode, and is checked before the body is read. Only `/healthz` is open.
- A request carrying an `Origin` or `Sec-Fetch-Site` header is refused with 403.
  The terminal sends neither, so this shuts out web pages. CORS is never enabled.
- The `Host` header must be in `security.allowed_client_hosts`.
- Every response carries an `X-Request-ID` generated by the gateway.
- Fields not listed here may be added. Clients must ignore unknown fields.
- Sensitive text never appears in a URL or query string.

### Errors

Any non-2xx response has this body:

```json
{
  "error": {
    "code": "provider_unavailable",
    "message": "The AI service isn't responding. Please try again in a moment.",
    "detail": "connect to 127.0.0.1:11434 refused",
    "retryable": true
  }
}
```

`message` is plain language, safe for any user, and never names a location,
because a gateway may not be on the user's computer. `detail` is technical and
sent only to callers holding `view_diagnostics`, otherwise it is `null`. Basic
mode shows only `message`.

| Code | HTTP | Meaning |
|---|---|---|
| `validation_error` | 422 | Request failed validation. |
| `auth_required` | 401 | Token missing or invalid. |
| `permission_denied` | 403 | Identity lacks the permission, or a browser origin was refused. |
| `not_found` | 404 | Resource missing or not visible to this caller. |
| `conversation_locality_changed` | 409 | The conversation began under a different locality. Start a new chat. |
| `request_too_large` | 413 | Request body or an attachment exceeds the limit. |
| `unsupported_attachment` | 415 | Attachment extension not accepted. |
| `busy` | 429 | The inference queue is full, or a previous turn has not finished. |
| `provider_unavailable` | 503 | Model server unreachable. |
| `model_not_installed` | 503 | No usable model for this request. |
| `model_load_failed` | 503 | The model server could not load the model. |
| `model_not_permitted` | 503 | Refused by policy, for example Ollama cloud access is on. |
| `context_too_large` | 422 | The message alone exceeds the context budget. |
| `timeout` | 504 | The model server stopped responding. |
| `provider_error` | 502 | The model server failed, or returned a redirect. |
| `internal` | 500 | Unexpected gateway failure. |

## Service endpoints

### `GET /healthz`

No authentication. Returns `{"status":"ok"}`. Reveals nothing else.

### `GET /v1/bootstrap`

Called at startup, retried until it succeeds, and called again after any failed
status poll or when `gateway.instance_id` changes.

```json
{
  "application": {
    "name": "Digital Commons",
    "version": "0.1.0",
    "stage": "beta",
    "notice": "Beta software. Not approved for production use or sensitive data."
  },
  "identity": {
    "user_id": "local.developer",
    "display_name": "Local Developer",
    "groups": ["all-staff", "finance"],
    "auth_mode": "local"
  },
  "permissions": {
    "advanced_mode": true,
    "manual_model_selection": true,
    "view_diagnostics": true,
    "search_documents": true,
    "allowed_tiers": ["fast", "standard", "advanced"]
  },
  "locality": {
    "kind": "this_device",
    "label": "On this computer",
    "description": "Your conversations are processed on this computer and are not sent to any outside AI service."
  },
  "suggestions": [
    {
      "id": "summarize",
      "title": "Summarize a document",
      "subtitle": "Get the key points quickly",
      "action": "attach",
      "prompt": "Summarize this document. List the key points and any deadlines or actions required."
    }
  ],
  "limits": {
    "max_message_chars": 15000,
    "max_attachments": 4,
    "max_attachment_bytes": 262144,
    "attachment_extensions": [".txt", ".md", ".csv", ".tsv"]
  }
}
```

`locality.kind` is `this_device`, `organization` or `demo`. It is computed by the
gateway, never read from configuration (see `docs/security.md`). The gateway
omits suggestions the caller cannot use.

`suggestions[].action` is one of:

- `prompt`: place `prompt` in the composer for the user to complete.
- `attach`: open the file picker, then place `prompt` in the composer.
- `attach_two`: as `attach`, keeping the picker open until two files are chosen.
- `documents`: turn on approved-document search, then place `prompt`.

### `GET /v1/status`

The terminal polls this every 5 seconds. The gateway serves a cached view that a
background task refreshes at most every 5 seconds.

```json
{
  "state": "ready",
  "reason": null,
  "summary": "Ready",
  "locality": { "kind": "this_device", "label": "On this computer", "description": "..." },
  "warmup": { "state": "ready", "message": null },
  "gateway": {
    "version": "0.1.0",
    "instance_id": "0f3c9a51",
    "uptime_s": 124,
    "address": "127.0.0.1:8000"
  },
  "inference": {
    "provider": "ollama",
    "kind": "ollama",
    "reachable": true,
    "version": "0.40.13",
    "error": null,
    "cloud_access_disabled": true,
    "missing_models": [],
    "warmup_model": "Gemma4:12b",
    "loaded_models": [
      {
        "name": "Gemma4:12b",
        "size_bytes": 6401126562,
        "gpu_bytes": 0,
        "context_tokens": 8192,
        "expires_at": "2026-11-01T21:15:13Z"
      }
    ]
  }
}
```

`state`:

| Value | Meaning |
|---|---|
| `starting` | Warm-up is running. |
| `ready` | Provider reachable and every enabled tier installed. |
| `degraded` | Reachable and at least one tier usable, but others are missing or warm-up failed. |
| `unavailable` | Nothing usable. `reason` is set. |
| `demo` | The mock provider is active. |

`reason` is `null`, `provider_unreachable`, `model_missing`, `model_load_failed`
or `cloud_access_enabled`.

`summary` is plain language for Basic mode. `warmup.state` is `idle`, `loading`,
`ready` or `failed` and records the last attempt, not whether the model is still
loaded. A reply that produces text from the warm-up model also sets it to `ready`,
and a warm-up still waiting behind that reply is skipped, because the model is
already loaded. `inference` is `null` unless the caller holds `view_diagnostics`.
`missing_models` holds `{tier, model, install_hint}`, with the hint written by the
gateway so the terminal needs no provider knowledge.

### `GET /v1/models`

Requires `manual_model_selection`.

```json
{
  "provider": "ollama",
  "tiers": [
    {
      "tier": "standard",
      "label": "Standard",
      "description": "General everyday work",
      "enabled": true,
      "available": true,
      "unavailable_reason": null,
      "model": "Gemma4:12b",
      "context_tokens": 8192,
      "max_output_tokens": 2048,
      "temperature": 0.4,
      "thinking": false
    }
  ]
}
```

`tier` is `fast`, `standard`, `advanced` or `specialist`. `specialist` is reported
with `enabled: false` until a Mixture of Experts server exists.

### `GET /v1/privacy`

Facts computed from running state, never fixed marketing text. Each statement
speaks only for what the gateway can actually establish.

```json
{
  "locality": { "kind": "this_device", "label": "On this computer", "description": "..." },
  "statements": [
    {
      "id": "processing",
      "label": "Where the AI runs",
      "value": "On this computer",
      "status": "ok",
      "detail": "Inference is handled by Ollama at 127.0.0.1:11434."
    }
  ],
  "notice": "Local processing alone does not make a system secure or compliant. This beta has not been approved for production use."
}
```

`label` and `value` are always free of technical words. `detail` is technical and
shown only in Advanced mode. `status` is `ok`, `info` or `warn`. A check that
fails is reported as `warn` in plain language, never omitted.

| Statement id | Establishes |
|---|---|
| `processing` | Where inference runs, and the real upstream host. |
| `external_ai` | The live result of the Ollama cloud check. |
| `cloud_fallback` | No fallback exists. |
| `telemetry` | Digital Commons sends none. An `info` note says Ollama itself may check ollama.com for updates. |
| `conversation_storage` | Where conversations and the text of attached files are kept, and for how long. `warn` when the folder may be open to other accounts: on Windows, a data folder outside the user profile and `%LOCALAPPDATA%`. |
| `logging` | What the gateway logs. Speaks for the gateway only. |
| `network_exposure` | The gateway bind, plus a connection test of the provider port on non-loopback addresses. `info`, and not "this computer", when `security.allowed_client_hosts` names a host other than loopback, because a proxy can then forward other computers to the gateway. |
| `encryption_at_rest` | Always `warn` in this beta: conversations are not encrypted. |
| `authentication` | `info` for a local token, `warn` for a shared token. |

## Chat

### `POST /v1/chat/stream`

Sends one user turn and streams the reply as Server-Sent Events.

```json
{
  "conversation_id": null,
  "message": "Summarize the attached policy.",
  "attachments": [
    { "name": "policy.txt", "media_type": "text/plain", "text": "..." }
  ],
  "tier": "auto",
  "assistant": "general",
  "use_documents": false,
  "regenerate": false
}
```

- `conversation_id`: `null` starts a new conversation. An id not owned by the
  caller returns `not_found`, for normal turns and for regenerate alike.
- `message`: may be empty when at least one attachment is present. The title then
  uses the first file name.
- `attachments[].text` is always UTF-8. The terminal decodes files before sending.
  The gateway validates the extension from `name`, and applies the size limit to
  the encoded text. `media_type` is informational.
- `tier`: `auto` by default. Any other value requires `manual_model_selection`,
  and must be in `allowed_tiers`.
- `assistant`: `general` or `code`. `code` requires `advanced_mode`. Both are
  server-defined. Clients cannot supply a system prompt.
- `use_documents`: search approved documents. Requires `search_documents`.
- `regenerate`: see the turn lifecycle. `conversation_id` is required, `message`
  is ignored and `attachments` must be empty.

### Turn lifecycle

1. **Before the response begins**: authentication, validation, the conversation
   locality check, permission checks, the queue-capacity check, routing, retrieval
   and context assembly. A failure here returns a normal error, writes nothing and
   creates no conversation. The terminal keeps the user's text and attachments in
   memory, and Try again resends them as a new `POST`. A conversation deleted while
   this runs returns `not_found` and stays deleted. A caller that closed the
   connection before this finished gets nothing written, because the gateway checks
   for that just before the write in rule 2.
2. **Immediately before `start`**: one transaction creates the conversation if new
   and inserts the user message, with attachment text as actually sent to the
   model. A file that did not fit at all is kept by name with no text. If the
   provider then refuses the prompt and the gateway retries with less, or a
   regenerate cuts a file further, the stored text is replaced by what was sent.
   Attachment text follows the same retention and delete rules, and is never
   returned by the API.
3. **When the turn ends**: the assistant message is written exactly once, only if
   its text is not blank (text of only spaces and line breaks counts as blank), with
   `finish_reason` `stop`, `length`, `cancelled` or `error`, and with the notices
   last sent for it. `start.message_id` and `done.message_id` are that row. A
   gateway crash writes no row. A turn whose conversation was deleted meanwhile
   discards its row.
4. **Regenerate** re-runs from the last user message using its stored text and
   attachments. `tier`, `assistant` and `use_documents` come from the request, and
   retrieval runs again under the caller's current groups. Any previous assistant
   row after that user message is replaced in the same transaction that writes the
   new one, and only if the new text is not blank. A file cut on the first turn gets
   the same `attachment_truncated` notice again, counted from the whole file.
5. **Context** includes every user row and every stored assistant row, whatever
   their `finish_reason`.
6. **Try again** after `start` means regenerate. Before `start` it means resend.
   The terminal shows Try again only when `retryable` is true, or after a lost
   connection.
7. **A POST to a conversation with an unfinished turn** waits up to 5 seconds for
   that turn's row, then returns `busy`.
8. Thinking text and retrieved passages are never stored or resent.

Closing the connection cancels generation at any point, including while queued.
Partial text is saved with `finish_reason: "cancelled"`. No terminal event is sent.
A connection already closed when the user message is about to be written gets
nothing written and nothing sent to the model (rule 1).

### Stream format

`text/event-stream`, LF line endings, one `data:` line per event. Clients ignore
any line beginning with `:`. A comment line `: ping` is sent at least every 10
seconds. The client treats 30 seconds with no bytes, or any end of stream without
`done` or `error`, as a lost connection.

Order: `start`, then at most one `citations`, then any of `status`, `thinking` and
`delta`, then exactly one of `done` or `error`. `citations` always precedes the
first `delta`.

One exception. When the provider refuses the prompt as too long before any
`thinking` or `delta`, the gateway retries once with less (see "Context budget"),
and corrects what it already said before anything else is sent:

1. `status` with phase `reading`, saying some of the request is being left out.
2. `notices`, always, holding the complete list for the shorter prompt. It replaces
   `start.notices`.
3. A second `citations` only if the sources changed. It replaces the first, and is
   sent with an empty list when no source fitted the shorter prompt.

Then the turn goes on as usual. In full, a retried turn sends `start`, at most one
`citations`, any `status`, then `notices`, a second `citations` if the sources
changed, then any of `status`, `thinking` and `delta`, then exactly one of `done` or
`error`.

```
event: start
data: {"request_id":"...","conversation_id":"...","message_id":"...","title":"Summarize the attached policy","route":{"requested_tier":"auto","tier":"standard","locality":"this_device","fallback_from":null,"model":"Gemma4:12b","provider":"ollama","reason":"Attachment present"},"context":{"estimated_tokens":1240,"budget_tokens":6144,"omitted_messages":0},"notices":[]}

event: citations
data: {"citations":[{"number":1,"document_id":"sample-remote-work","title":"Remote Work Policy","department":"Human Resources","classification":"public","version":"2.1","document_date":"2026-03-01","source_filename":"remote-work-policy.md","section":"Eligibility","page":null,"snippet":"Employees may...","sample":true}]}

event: status
data: {"phase":"loading_model","message":"Getting ready. The first response can take a few minutes."}

event: notices
data: {"notices":[{"code":"attachment_truncated","message":"Only part of policy.txt was read: about 34%, 14,600 of 42,000 characters."}]}

event: thinking
data: {"text":"..."}

event: delta
data: {"text":"Here is"}

event: done
data: {"message_id":"...","finish_reason":"stop","usage":{"prompt_tokens":152,"completion_tokens":388,"total_tokens":540,"first_token_ms":2210,"total_ms":61000,"load_ms":78,"tokens_per_second":6.4,"estimated":false}}

event: error
data: {"code":"provider_unavailable","message":"...","detail":null,"retryable":true}
```

- `route.model`, `route.provider` and `route.reason` are present only for callers
  holding `view_diagnostics`. The terminal also hides them in Basic mode.
- `status.phase` is `queued`, `loading_model`, `reading` or `generating`. The
  terminal displays `status.message` verbatim for any phase, with elapsed time, so
  new phases are non-breaking. When nothing else applies it shows "Thinking…".
- `reading` is sent when `context.estimated_tokens` exceeds 1000.
- `notices[]` holds `{"code":"...","message":"..."}`, shown to the user. Codes:
  `attachment_truncated` (a file was cut or not read, counted from the whole file),
  `history_trimmed`, `attachment_left_out` (trimming removed an earlier turn that
  carried a file, named in the message), `tier_fallback`, `documents_none_found`
  (retrieval matched nothing) and `documents_left_out` (retrieval matched, but no
  passage fitted beside the message and files).
- `citations[].sample` is `true` for a passage from the invented sample collection,
  marked by `sample: true` in the document's front matter. The terminal labels such
  a source, and the passage reaches the model labelled as an invented sample.
- `done.finish_reason` is `stop` or `length`.
- `usage.first_token_ms` counts the first `thinking` or `delta` chunk.
- `usage.estimated` is `true` when the provider gave no token counts.
- If `done` has `finish_reason` `length` and no text arrived, show "The assistant
  ran out of room before answering. Try again, or ask a shorter question."

### Context budget

`budget_tokens = context - max_output`. The budget covers the system prompt,
history, attachments, retrieved passages and the current message. Tokens are
estimated as `ceil(chars / 4) + 16` per message.

Fill priority: system prompt, current message, current attachments, retrieved
passages, then newest history.

- Current attachments share what remains equally, and unused share passes to the
  other. Text is cut from the tail, and each cut file gets an
  `attachment_truncated` notice saying how much of the whole file was read.
- When history must be trimmed, drop oldest turns until the prompt is at most 70%
  of budget, so later turns stay cached by the model server.
- If the provider still reports the prompt is too long, scale content down using
  the reported size, retry once, then emit `context_too_large`. The retry is
  announced with a `notices` event and, if the sources changed, a second
  `citations` (see "Stream format"). When the system prompt and the message alone
  exceed the scaled budget, there is nothing to cut, so no retry is sent and the
  turn ends with `context_too_large`.

## Conversations

Scoped to the authenticated user. Another user's conversation returns `not_found`,
never `permission_denied`.

### `GET /v1/conversations`

```json
{
  "conversations": [
    {
      "id": "...",
      "title": "Remote work eligibility",
      "assistant": "general",
      "locality": "this_device",
      "created_at": "2026-11-01T20:39:12Z",
      "updated_at": "2026-11-01T20:41:02Z",
      "message_count": 4
    }
  ]
}
```

Most recently updated first. Optional `limit`, default 100, maximum 500.
`assistant` is the latest turn's value.

### `GET /v1/conversations/{id}`

The summary fields plus `messages`:

```json
{
  "id": "m1",
  "role": "assistant",
  "content": "...",
  "created_at": "2026-11-01T20:39:12Z",
  "attachments": [{ "name": "policy.txt", "media_type": "text/plain", "chars": 4120 }],
  "citations": [],
  "notices": [],
  "route": null,
  "usage": null,
  "finish_reason": "stop"
}
```

- `role` is `user` or `assistant`. Attachment text is not returned. `chars` is the
  length of the text that was sent, which is 0 for a file that did not fit.
- `notices` are the ones last sent with that reply, in the stream's shape, so a
  reopened chat shows them again. A user message has none.
- `finish_reason` drives the note shown on reopen: `cancelled` shows "Stopped",
  `length` shows "This reply was cut short.", `error` shows "This reply was
  interrupted."
- `citations` are rebuilt on read through the permission filter. A citation the
  caller may no longer see is returned as `{"number": 2, "withheld": true}`.

### `DELETE /v1/conversations/{id}`

Returns 204. The conversation, its messages and attached file text are removed
from the database.

### `DELETE /v1/conversations`

Deletes all of the caller's conversations. Returns `{"deleted": 12}`.

## Documents

There is no separate search endpoint in this beta. Approved documents are reached
through `use_documents` on a chat turn. Permission filtering happens on the
gateway before any ranking, and a caller cannot learn that a hidden document
exists.

## Model host contract

The organization model server only has to implement this. It stores nothing and
runs no routing, retrieval or conversation logic. The local gateway remains the
only conversation store and policy point. This gateway can also serve the
contract, as a stand-in, with `inference_service.enabled: true`.

### `GET /healthz`

Returns 200 when available.

### `POST /v1/inference/stream`

Requires `Authorization: Bearer <service token>`.

```json
{
  "tier": "standard",
  "messages": [
    { "role": "system", "content": "..." },
    { "role": "user", "content": "..." }
  ]
}
```

The server maps `tier` to its own model and enforces its own limits, returning
`context_too_large` on overflow. The stream uses the format above with only these
events, in this order: any of `status`, `thinking` and `delta`, then exactly one
of `done` or `error`. `done` also carries `model`. Pings are mandatory. Closing the
connection cancels generation.
